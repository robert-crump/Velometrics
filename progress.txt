## Issue #226 -- Speed IQ: braking events card on Ride Detail (tracer bullet)
Completed: 2026-10-04

### What was done

- `BrakingDetector` (pure, domain/service): per record-to-record step,
  `E = ½m(v₁²−v₂²) + m·g·(h₁−h₂) + pedal work − drag − rolling`, with speed smoothed over 3 s and
  altitude over ~10 s (both centred). A step's P_brake = E / dt. Runs above 150 W lasting >= 2 s are
  joined across gaps < 5 s, and an event counts from 1.5 kJ. Penalty = E / P, where P = median of
  the pedalling samples (power > 0, >= 2 km/h). Record gaps > 5 s (timer pauses) split the stream.
  m = 85 kg (constant until #228); CdA 0.37, Crr 0.013, rho 1.225. All thresholds are in `CyclingConstants.SPEED_IQ_*`.
- The event km and the lowest speed come from the slowest record. The search continues past the
  event's last step while the speed keeps falling, because the last metres to a halt brake below
  the threshold. The peak is the fastest record before the slowest one.
- `CyclingSession.speedIq` is computed in `SessionMetricsCalculator` (power rides only) and stored
  as two JSON columns, `speedIqSummary` and `speedIqEvents` (top 5), in Room v24 (MIGRATION_23_24).
  Import-time only, no backfill. A ride without altitude stores `hasElevation=false`.
- Ride Detail drawer: a "Speed IQ" section card after Speed: `Braking 1:13 · 4 events`, then rows
  like `km 10.1 · 31 s braking · 42→0 km/h`, or "No elevation data". No card when `speedIq` is null
  (no power, or imported before this change).
- Demo rides: 2–13 events each, with stops and the same corners recurring per loop.
- Deviation: with this formula, #223's worked example (85 kg, −5 %, 50→0 km/h in 15 s) gives
  ≈ 9.1 kJ / ≈ 48 s, not ≈ 10.9 kJ / 57 s. Drag over the stop is ~2.3 kJ. The test asserts 9.1 kJ.
- Not done: no visual check on a device; README screenshots don't show the card yet.

`testDebugUnitTest` (incl. `BrakingDetectorTest`, migration 23->24, demo ride Speed IQ) and
`assembleDebug` pass. The first test run hit a one-off native Robolectric crash
(libandroid_runtime finalizer); the rerun was clean.

## Issue #222 -- Cardiac drift: add tips
Completed: 2026-10-04

### What was done

- Plan from a /grill-me session, posted as a comment on #222. The recap redo (two prose sentences instead of stat
  lines) is split out as #224.
- `CardiacDriftBand` renamed to LOW / MEDIUM / HIGH (5 % / 10 % unchanged); the HR card now reads "7.2% (medium)".
- FIT record temperature is read into `Datapoint.temperatureC`; `avgTemperatureC` is persisted at import (no
  backfill).
- `CardiacDriftAdvisor` (pure) ranks up to two causes for MEDIUM/HIGH drift: HEAT (avg >= 25 °C), INTENSITY
  (NP/FTP on the ride date >= 0.75), DURATION (>= 1.3x the median of the rider's >= 60 min rides in the 6 weeks
  before, needs >= 3 such rides). An empty list means the generic hydration/food advice.
- `CardiacDriftAdviceService.evaluate` runs at import. New columns `cardiacDriftCauses` (comma-separated codes,
  "" = none fired) and `cardiacDriftDurationBaselineSec` (Room v23, MIGRATION_22_23).
- Backfill: `CardiacDriftAdviceBackfill` runs at app start and only touches drift >= 5 % rows with null causes.
  The debug "Apply re-tag" Settings row also calls `recomputeAll`.
- Session Detail: a "Cardiac drift" block under the recaps in `RideSummaryGrid`, two sentences rendered at display
  time (diagnosis with evidence, then advice). It says "start riding earlier" only for hot rides started after
  11:00, adds "eat every 30–45 min" on rides >= 2 h, and has no fatigue/TSB rule and no elite tips.
- Demo data: records carry a temperature (12–19 °C rising over the block). The hero ride is now a 14:xx start at
  ~28–30 °C with a lower HR baseline and more drift (8.0 %, HEAT). The other rides' random streams are unchanged.
  Herzogenrath ride 22 drifts 7.5 % by itself, so it shows INTENSITY advice.
- Not done: `docs/screenshots/*.png` still show the old hero ride until `./gradlew readmeScreenshots` is rerun.

`testDebugUnitTest` (incl. new `CardiacDriftAdvisorTest`, `CardiacDriftAdviceServiceTest`, migration 22->23) and

## Issue #220 -- README screenshots: ./gradlew readmeScreenshots end to end (home.png)

  picks the one running `emulator-*` (or `ANDROID_SERIAL`, which must report `ro.kernel.qemu=1`), installs both
  APKs, `pm clear`s the app, overrides the display to 1080x2400 @ 420 dpi, enters demo mode (12:00, full battery,
  full Wi-Fi with `fully true`, no mobile/status icons), runs the gated test via `am instrument`, and in a `finally`

  `cmd statusbar send-disable-flag notification-icons` does (reset to `none` afterwards).
